# KPI 기간 조회 — 설계

- 작성일: 2026-10-28
- 브랜치: `feat/kpi-period-view`
- 대상 화면: 실시간 KPI(`/kpi`), AI 성능지표(`/ai`), 원가·납기(`/cost`)

## 1. 의도와 배경

지금 KPI·AI 화면의 생산·검사 지표는 **KST 오늘 0시 이후**만 집계한다(`v_daily_kpi`, `v_ai_metrics`, `fn_hourly_production_today`).
원가·납기는 **최근 30일 고정**이다. 날짜가 바뀌면 전날 수치를 화면에서 볼 수 없다. 원본 1분 패킷은 DB에 그대로 남아 있다.

사용 목적(사용자 발언):
- 회사가 관리 목적으로 쓴다.
- 평가위원이 1개월, 2개월, 3개월처럼 **누적 데이터**를 보려 한다. 2026-11 말 평가 때 이 화면으로 KPI 달성 여부를 확인한다.

### 사용자 요구 (확정)
1. 기간을 골라서 데이터를 본다. 보여줄 데이터는 다음 두 가지다.
   - 기간 안의 **날짜별 데이터**
   - 그 기간의 **집계값**. 평균이 맞는 지표는 평균으로, 합산이 맞는 지표는 합산으로 낸다.
2. KPI, AI, 원가 화면에 모두 적용한다.
3. 날짜(기간)를 볼 때는 "설비별 가동 상태"를 숨긴다.

### 성공 기준
- 평가위원이 "최근 90일"을 누르면 KPI 카드에 90일 누적 기준 실적과 목표 달성 여부가 나온다. 아래에는 90일치 날짜별 표와 합계·평균 행이 나온다.
- 기간을 고른 채 KPI → AI → 원가 탭을 오가도 같은 기간이 유지된다.
- 기간을 고르지 않은 기본 화면("오늘")은 지금과 **완전히 같다**.

## 2. 목표 / 비목표 / 안티골

- G1. 기간 선택 UI(프리셋 + 직접 지정)를 추가하고, 기간을 URL 쿼리로 보관해 세 탭이 공유한다.
- G2. KST 날짜별 집계 RPC를 추가한다. 데이터가 없는 날도 0으로 한 행을 만든다.
- G3. 세 화면 모두 기간 모드에서 카드가 기간 집계값을 보여주고, 날짜별 표와 합계·평균 행을 보여준다.
- G4. 기간 모드에서는 설비별 가동 상태를 숨긴다.

- 비목표: LOT 이력 탭과 관리자 화면의 기간 조회. LLM 분석(`llm-analyze`)의 기간 연동(지금처럼 최근 30일 고정). PDF 리포트. 시간 단위 드릴다운.
- 비목표: 기존 뷰·RPC 수정이나 삭제. "오늘" 모드는 기존 경로를 그대로 쓴다.
- 안티골: 비율 지표(불량률, 시간당 생산량 등)를 **일별 비율의 단순 평균**으로 내는 것. 생산이 적은 날의 비율이 과대 반영되어 평가 수치가 틀어진다. 반드시 총합 ÷ 총합(가중 평균)으로 낸다.
- 안티골: 데이터 없는 날이 표에서 빠지는 것, 또는 0/NaN이 비율 칸에 찍히는 것. 행은 남기고 비율 칸은 `—`로 표시한다.
- 안티골: 기간 모드가 "오늘" 화면의 숫자나 레이아웃을 바꾸는 것(평가 직전 회귀 위험).

## 3. 기간 모델

- 기간 = KST 날짜 `from` ~ `to`(양 끝 포함). URL은 `?from=YYYY-MM-DD&to=YYYY-MM-DD`이다.
- **쿼리가 없으면 "오늘" 모드**이고 기존 화면을 그대로 보여준다.
- 쿼리가 있으면 "기간 모드"이다. 오늘 하루만 고른 경우(`from=to=오늘`)도 쿼리가 있으면 기간 모드다.
- 유효성(클라이언트와 SQL 모두): `from ≤ to`, `to ≤ KST 오늘`, 기간 일수 ≤ 366, `from ≥ 2020-01-01`. URL 값이 잘못되면 "오늘" 모드로 돌아가고 안내 문구를 한 줄 보여준다.
- 프리셋(종료일은 모두 KST 오늘): 오늘(쿼리 제거), 최근 7일, 최근 30일, 최근 60일, 최근 90일, 이번 달(1일~오늘), 지난 달(1일~말일, 종료일이 과거). 직접 지정은 `<input type="date">` 두 개와 "조회" 버튼이다.
  - "최근 N일" = 오늘 포함 N일, 즉 `from = 오늘 − (N−1)`. 평가위원이 말한 1·2·3개월을 30·60·90일로 대응시킨 것은 **설계자 판단**이다.
- 탭 이동(`TabBar`, `MobileNav`) 시 `/kpi`, `/ai`, `/cost` 사이에서는 쿼리를 유지한다. 그 밖의 탭으로 갈 때는 쿼리를 뺀다.
- 기간 모드 상단에 배너를 둔다: `조회 기간 2026-08-01 ~ 2026-10-28 (89일) · 실시간 아님`.

## 4. 데이터 (migration 1파일 + rollback 1파일)

### 4.1 `fn_kpi_daily(p_from date, p_to date)`

KST 날짜별로 한 행씩 반환한다. `generate_series`로 기간의 모든 날을 만들고, 데이터가 없는 날은 0을 넣는다.

| 컬럼 | 타입 | 정의 (기존 뷰와 같은 장비 필터) |
|---|---|---|
| `day` | date | KST 날짜 |
| `production` | int | `equipment_metrics.output_count` 합 — `devices.role='primary_output' and active` |
| `runtime_sec` | int | 같은 대상의 `runtime_seconds` 합 |
| `inspected` | int | `vision_inspector_metrics.total_inspected` 합 — `devices.type='vision_inspector' and active` |
| `defects` | int | `defect_count` 합 |
| `unknown` | int | `unknown_count` 합 |
| `inspection_time_sec` | numeric | `inspection_time_seconds` 합 |
| `claims` | int | `claims.received_at`의 KST 날짜별 건수 |

- 날짜 귀속: `(bucket_at at time zone 'Asia/Seoul')::date`. 범위 필터는 인덱스를 타도록 `bucket_at >= (p_from::timestamp at time zone 'Asia/Seoul') and bucket_at < ((p_to + 1)::timestamp at time zone 'Asia/Seoul')`로 쓴다.
- 유효성을 어기면 `raise exception`(§3 규칙). plpgsql, `stable`, `security invoker`, `set search_path = public`.
- 권한: `revoke all … from public, anon` 후 `grant execute … to authenticated`. 기반 테이블 RLS가 authenticated 읽기를 이미 허용한다.
- 정렬: `day` 오름차순.
- 테넌트: 이 프로젝트는 단일 회사 전용이라 `tenant_id`가 없다. 기존 구조를 따른다(2026-10-26 스펙 §4와 같음).

### 4.2 LOT·인력 지표 (새 SQL 없음)
- 작업공수: 기존 `v_lot_manhour`를 `ended_at`이 기간 안(KST `from` 0시 ≤ `ended_at` < `to+1` 0시)인 행으로 클라이언트에서 필터한다.
- 리드타임: 기존 `v_lot_leadtime`를 `shipped_at` between `from` and `to`로 필터한다.
- 인력 지표: `hr_kpi_records`에서 `measured_on`이 기간 안에 있는 기록 중 지표별 최신값을 쓴다(기존 `pickLatestHrKpi` 재사용).
- 목록 조회 상한은 500건(초과 시 표 아래 "최근 500건만 표시" 안내). 평균·합계는 상한과 무관하게 정확해야 하므로, 집계는 전체 행 기준이다. 500건을 넘는 경우는 사실상 없다(LOT 300kg 단위). 그래도 집계용 조회는 필요한 컬럼만, 상한 없이 가져온다.

## 5. 집계 규칙 (합산 vs 평균)

비즈니스 로직은 `src/lib/services/periodKpi.ts`에 둔다(컴포넌트 금지, 전역 규칙).

| 지표 | 기간 집계 | 날짜별 표 칸 |
|---|---|---|
| 생산수량 | **합계** | 그날 합 |
| 가동시간 | **합계** (h 표시) | 그날 합 |
| 시간당 생산량 | **평균** = Σ생산 ÷ (Σ가동초/3600) | 그날 비율, 생산 0이면 `—` |
| 작업시간/ea | **평균** = Σ가동초 ÷ Σ생산 | 같음 |
| 일 목표 달성률 | 표 칸만: 그날 생산 ÷ `daily_production` × 100. 합계 행은 `—` | 그날 값 |
| 검사수 / 불량수 / 재검수 | **합계** | 그날 합 |
| 불량률 (KPI 품질) = AI 불량 검출율 | **평균** = Σ불량 ÷ Σ검사 × 100 | 그날 비율, 검사 0이면 `—` |
| 검사 처리량 | **평균** = Σ검사 ÷ (Σ검사초/3600) | 같음 |
| 재검율 | **평균** = Σ재검 ÷ Σ검사 × 100 | 같음 |
| 클레임 | **합계** | 그날 건수 |
| LOT당 작업공수 | **평균**(기간 내 종료 LOT의 평균), 보조로 **합계** man-hour와 LOT 수 | LOT별 표 |
| 납기 리드타임 | **평균**(기간 내 출하 LOT의 평균), 보조로 LOT 수 | LOT별 표 |
| 직무 전환율·만족도 | 기간 내 **최신값**(누적 상태 지표라 평균·합계가 맞지 않음) | — |

- "평균"은 모두 **총합 기반 가중 평균**이다. 화면 산출식 박스에 `기간 총합 기준`이라고 적는다.
- 날짜별 표 마지막 행은 `기간 합계·평균`이다. 각 칸은 위 규칙대로 채우고, 칸 머리 또는 셀에 `합계`/`평균` 구분이 드러나게 한다.
- 반올림은 기존 뷰와 같은 자릿수(시간당 생산량·처리량 정수, 비율 2자리, sec/ea 2자리, man-hour 1자리 표시)로 한다.

## 6. 화면

### 공통
- `PeriodPicker` 컴포넌트: 세 페이지 상단에 둔다. 프리셋 버튼 + 직접 지정 + 현재 기간 배너.
- 기간 모드 데이터 훅: `usePeriodDaily(from,to)`(RPC), `usePeriodLots(from,to)`, `usePeriodHrKpi(from,to)`. 기간이 과거로 끝나는 경우 30초 자동 재조회는 꺼도 되고 켜 둬도 된다(빌더 재량).

### `/kpi` 기간 모드
- 공통·자율 성과지표 카드: 같은 카드에 기간 집계값을 넣는다. 데이터 없음 사유는 `기간 내 생산 실적 없음` 등 "오늘"을 "기간 내"로 바꾼 문구다. 클레임 카드 note는 `선택 기간 합계 (목표는 분기 기준)`이고, 달성 판정은 기존 분기 목표와 그대로 비교한다(**설계자 판단**).
- "오늘 목표 달성률" 막대: 숨긴다. 일자별 표의 달성률 칸으로 대신한다.
- "시간대별 생산량" 차트 → "일자별 생산량" 막대 차트(일 목표선 포함)로 바꾼다.
- "LOT별 작업공수" 차트: 기간 내 종료 LOT 중 최근 10건.
- **설비별 가동 상태: 숨긴다.**
- 최근 알람: 그대로 둔다(실시간 목록임을 그대로 표시, **설계자 판단**).
- 아래에 **날짜별 표**를 추가한다: 날짜 · 생산수량 · 가동시간(h) · 시간당 생산량 · 작업시간/ea · 일 목표 달성률 · 검사수 · 불량수 · 불량률 · 클레임, 그리고 합계·평균 행.

### `/ai` 기간 모드
- 세 카드: 기간 총합 기준 값.
- "AI 성능 추이" 차트: 기간의 날짜별 검출율·재검율. 제목은 `AI 성능 추이 (선택 기간)`. "오늘" 모드 차트는 손대지 않는다.
- 날짜별 표: 날짜 · 검사수 · 불량수 · 재검수 · 검사시간(h) · 불량 검출율 · 처리량 · 재검율, 그리고 합계·평균 행.
- PRF 차트(mock)와 하단 설명은 그대로 둔다.

### `/cost` 기간 모드
- 작업공수 히어로: `LOT당 작업공수 (선택 기간 평균)` + 보조 문구 `완료 LOT n건 · 총 x man-hour`. LOT 표: 기간 내 전부(최신순, 상한 500).
- 납기 히어로: 기간 평균 + `출하 LOT n건`. LOT 표: 기간 내 전부.
- LLM 분석 버튼: 그대로 둔다(최근 30일 기준). 버튼 옆에 `최근 30일 기준` 문구를 추가한다.

### 300줄 규칙
`KpiPage`·`CommonKpiSection`이 300줄을 넘을 것 같으면 분리 전에 사용자에게 먼저 보고한다(전역 규칙). 기간 모드 렌더링은 별도 컴포넌트(예: `KpiPeriodView`)로 처음부터 나누어 기존 파일 증가를 최소화하는 것을 권장한다.

## 9. 설계자 판단 목록 (사용자 확인 권장)

1. 1·2·3개월 = 최근 30·60·90일 프리셋. 이번 달·지난 달 프리셋도 추가.
2. "오늘" 모드(쿼리 없음)는 기존 화면 그대로 둔다. 오늘 하루를 기간으로 직접 고르면 기간 모드(가동 상태 숨김).
3. 비율 지표의 기간 평균 = 총합 기반 가중 평균.
4. 인력 지표 = 기간 내 최신값. 클레임 = 기간 합계, 분기 목표와 그대로 비교.
5. 기간 모드에서 "오늘 목표 달성률" 막대를 숨기고 일자별 표 칸으로 대신한다.
6. 최근 알람·LLM 분석은 기간과 연동하지 않는다.
7. 최대 조회 기간 366일.
